# Проект Yambda

## Этапы

1. Проверить данные и построить витрины.
2. Собрать дашборд и проверить продуктовые гипотезы.
3. Подготовить выводы и предложения по A/B-тестам.

## Разделение первого этапа

| Участник | Ноутбук | Код | Результат |
|---|---|---|---|
| 1 | `01_source_quality.ipynb` | `prepare_events.py` | подготовленные события |
| 2 | `02_product_mart.ipynb` | `product_mart.py` | витрина по дням |
| 3 | `03_user_mart.ipynb` | `user_mart.py` | витрина пользователей |
| 4 | `04_track_mart.ipynb` | `track_mart.py` | витрина треков и общая сверка |

После подготовки событий витрины 2–4 можно считать параллельно.

## Определения

- День: `timestamp // 86400`.
- Новая сессия: перерыв больше 1800 секунд.
- Listen+: прослушано больше 50% трека.
- Повтор: `played_ratio_pct > 100`.
- `is_organic = 0` — рекомендация, `is_organic = 1` — органика.

## Запуск

```powershell
python scripts/download_data.py
python scripts/build_marts.py
```

Исходные данные, промежуточная DuckDB и Parquet-витрины хранятся локально в
`data/` и не добавляются в Git.
